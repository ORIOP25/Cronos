## Brand & Style

This design system defines the visual identity of a school schedule management
application built for Portuguese professional education institutions. The
aesthetic is warm, authoritative, and premium — projecting institutional trust
while remaining modern and approachable.

The system follows a **60-30-10 color rule**: 60% warm-white surfaces create
breathing room, 30% deep brown provides structural weight and navigation
anchoring, and 10% amber-gold delivers focused accents and interactive
highlights. This ratio ensures the gold never overwhelms; it punctuates rather
than decorates.

The emotional tone is calm confidence. The brown palette — drawn from natural
earth and dark wood — signals stability and permanence. The amber-gold accent
adds warmth without tipping into luxury excess. Together they create an
environment where educators feel in control of complex scheduling workflows.

## Colors

### Brand Palette

The core brand sequence moves from warm off-white through deepening browns:

| Step  | Swatch     | Purpose |
|-------|------------|---------|
| 50    | `#faf8f5`  | Page background — never pure white, always slightly warm |
| 100   | `#f5f0eb`  | Card headers, alternating table rows, muted surfaces |
| 200   | `#ede5dd`  | Deeper surface for nested containers and hover states |
| 300   | `#fef3c7`  | Pale yellow for alert backgrounds and selected cards |
| 400   | `#f0b429`  | Brighter yellow for hover glow and decorative elements |
| 500   | `#d4940b`  | **Amber-gold accent** — CTAs, active states, highlights, divider lines |
| 600   | `#8b6f5c`  | Light brown — secondary text, muted labels, disabled states |
| 800   | `#5c3d2e`  | **Medium brown primary** — buttons, headings, links, brand mark |
| 950   | `#3d2b1f`  | **Deepest brown** — sidebar background, dark sections, hero depth |

### Semantic Tokens

Never use raw hex codes in components. Always consume through semantic tokens:

- **Surfaces:** `surface` (page), `surface-bright` (cards), `primary-container`
  (headers), `surface-container` through `surface-container-highest` (progressively
  deeper nesting).
- **Text:** `on-surface` (`#1a1512` — warm dark, never pure black), `on-surface-variant`
  (`#8b6f5c` — secondary), `text-inverse` (`#ffffff`).
- **Actions:** `primary` (brown for main actions), `tertiary` (gold for emphasis),
  `secondary` (muted brown for neutral actions).
- **States:** `success` (teal `#15803d`), `warning` (gold `#d4940b`),
  `error` (red `#b91c1c`), `info` (blue `#2563eb`). Each has paired accessible
  text tokens for WCAG AA compliance.

### The Gold Rule

Amber-gold (`#d4940b` / `#f0b429`) must only be used as an accent — on buttons,
border highlights, divider lines, and small decorative elements. It must never
be used as body text on a light background. When used as a badge background,
text must be the dark `on-tertiary` (`#1a1512`) to maintain contrast.

### Sidebar & Dark Surfaces

The sidebar uses a gradient from `#3d2b1f` to `#2a1a0f` with light text
(`#faf8f5`). Links appear at 75% opacity, muted sections at 55% opacity.
The gold accent (`#d4940b`) marks active navigation items with a 3px vertical
bar.

### Operational State Colors

Class schedule states use a consistent visual language:

- **Given** (aula dada): Teal — success, completion
- **Gap** (falta): Red — attention required
- **Substituted** (substituição): Gold — noteworthy but resolved
- **Open** (em aberto): Dark brown — pending action
- **Planned** (planeada): Muted beige — neutral, future

Each state card uses a 3px left border in the state color against a 10% opacity
background, ensuring states are distinguishable even for color-blind users.

### Subject Color Palette

A 10-color deterministic palette maps subject IDs to consistent visual markers
across the application:

```
#5c3d2e  #15803d  #2563eb  #d4940b  #9333ea
#0891b2  #c2410c  #4f46e5  #0d9488  #be185d
```

Colors are assigned via modulo hashing (`subjectId % 10`), ensuring the same
subject always gets the same color regardless of list ordering or which component
renders first.

## Typography

The system pairs two typefaces for a clear hierarchy: **Playfair Display** for
editorial moments and headings, **Outfit** for body text and UI.

### Usage Hierarchy

| Role | Family | Weight | Size | Notes |
|------|--------|--------|------|-------|
| Hero title | Playfair Display | 700 | 3–6rem fluid | Extra-tight line height (0.94–1.05), deep negative tracking |
| Section headings | Playfair Display | 700 | 1.8–3.2rem | Used on marketing page vision/outcome sections |
| Card titles | Playfair Display | 700 | 1.25–1.5rem | Slight negative tracking |
| Editorial pull quotes | Playfair Display | 400 italic | 1rem | Created via `.text-editorial` utility |
| Body text | Outfit | 400 | 0.92–1.2rem | 1.7× line height for readability |
| Labels & buttons | Outfit | 600 | 0.7–0.88rem | Uppercase, widely tracked |
| Table headers | Outfit | 700 | 0.72rem | Uppercase, extra-wide tracking (0.15em) |

### Typography Principles

1. **Playfair is reserved for headings only.** It never appears in body copy,
   form labels, buttons, or data tables. This restraint preserves its editorial
   impact.
2. **Outfit carries all UI weight.** Its geometric clarity and generous x-height
   make it readable at small sizes (table headers, form labels, badge text).
3. **Uppercase labels signal affordance.** Buttons, nav links, kickers, and
   table headers use uppercase with wide tracking — a pattern that says "this
   is interactive" or "this is structural metadata."
4. **No font-weight below 300 for body.** The lightest weight used (Outfit 300)
   appears only in decorative contexts or very large display settings.

## Layout & Spacing

### The 8px Grid

All spacing derives from an 8px base unit. The scale runs: 4, 8, 16, 24, 40,
64, 80, 140, 160px.

### Section Rhythm

Marketing page sections use generous vertical padding (140–160px desktop, 80px
mobile) to create distinct visual chapters. The dark section (`#3d2b1f`
background) alternates with light sections to create clear information
architecture.

### Maximum Width

The marketing layout is capped at 1180px with centered auto-margins. The
application dashboard uses a fluid layout controlled by the CoreUI sidebar
width plus a natural content area.

### Card & Table Spacing

- Cards: 20px body padding, 16px/20px header padding
- Tables: 18px/20px cell padding, generous to reduce density stress
- Buttons: 10px/24px (standard), 12px/28px (primary), 16px/40px (large CTA)

### Glass Container Spacing

Glass surfaces (`.zen-glass`) use `rgba(250,248,245,0.72)` backgrounds with
20px backdrop blur. They're used sparingly — primarily on the marketing page
for feature cards that float above contextual backgrounds.

## Elevation & Depth

### The Surface Stack

Depth is communicated through three mechanisms: background tint darkening,
shadow spread, and border definition.

1. **Page (Level 0):** `#faf8f5` — no shadow, no border
2. **Card (Level 1):** White surface, `1px solid #e0d6cc` border, 20px soft shadow
3. **Elevated Card (Level 2):** White surface, border retained, shadow deepens on hover
4. **Modal/Overlay (Level 3):** White surface on `rgba(26,21,18,0.35)` backdrop
5. **Toast (Level 4):** Glass-morphism surface at 92% opacity with 12px blur,
   highest z-index

### Shadow Philosophy

All shadows use the deepest brown (`#3d2b1f`) as their base rather than pure
black, making them feel organic and integrated with the warm palette. Shadow
opacity is kept very low (4–20%) to prevent a "dirty" gray cast.

### Glass Effect

`.zen-glass` achieves a frosted-glass look with `rgba(250,248,245,0.72)`,
`backdrop-filter: blur(20px)`, and a subtle `1px` border at 8% brown opacity.
Toasts use a similar approach at 92% opacity with 12px blur. These effects
are used sparingly to avoid performance degradation from backdrop-filter.

## Shapes

### Corner Radius Philosophy

The system uses a deliberate mix of sharp and rounded elements:

- **Zero radius (square):** Buttons, brand mark, hero art blocks, pricing cards
  on the marketing page. The sharp corners convey precision and institutional
  seriousness.
- **4px radius:** Badges, state cards, toast notifications. Slightly softened
  for small elements.
- **12px radius:** Dashboard cards, modals. A comfortable rounding that signals
  containment without feeling playful.
- **16px radius:** Selected larger containers.

This split creates visual tension between the "editorial" squareness of the
marketing presence and the "functional" softness of the application dashboard.

## Motion

### Timing & Easing

The system uses two primary easing curves:

- **Zen Reveal** (`cubic-bezier(0.2, 0.8, 0.2, 1.0)`): A custom deceleration
  curve that starts fast and settles gently. Used for page-load reveals,
  toast slide-in, link underline animation, and button hover lifts.
- **Luxury Slide** (`cubic-bezier(0.25, 0.46, 0.45, 0.94)`): A smoother
  transition for overlay reveals and decorative elements.

### Duration Scale

- 100ms: Instant (color shifts on hover)
- 200ms: Fast (transform lifts, box-shadow changes)
- 300ms: Normal (underline expansion, border transitions, column resizing)
- 400ms: Slow (button hover transitions, card border-color shifts)
- 500ms: Luxury (hero art overlay slides)
- 1200ms: Page reveal (`.zen-reveal` entrance animation)
- 1600ms: Shimmer (skeleton loading animation)

### Staggered Reveals

The `.zen-stagger-*` utility classes (stagger-1 through stagger-6) apply
incremental 100ms delays to `.zen-reveal` elements, creating sequential
entrance animations for grids of cards, feature lists, and section content.

### Skeleton Loading

Skeleton placeholders use a horizontal shimmer gradient that sweeps across the
element. The gradient uses three brand-token stops: `outline-variant` (beige
border) → `primary-container` (warm surface) → `outline-variant`, with a
`200%` background-size animated over 1.6s.

### Scroll Behavior

The HTML root has `scroll-behavior: smooth` for in-page anchor navigation.

### Reduced Motion

The `prefers-reduced-motion: no-preference` media query gates all animated
transitions on marketing cards, feature images, and navigation link underlines.

## Icons

The system uses `@coreui/icons` (v3) rendered through `@coreui/icons-react`.
Icons follow the structural brown palette — using `primary` (`#5c3d2e`) for
interactive icons and `on-surface-variant` (`#8b6f5c`) for decorative or
metadata icons. Icon size is typically 16–20px for UI contexts and 64px for
marketing feature icons.

## Components

### Buttons

Buttons follow a consistent vocabulary:

- **Primary:** Solid brown (`#5c3d2e`), white text, sharp corners, lifts 2px on
  hover with shadow deepening.
- **Accent (Gold):** Solid amber-gold (`#d4940b`), dark text, used for
  high-emphasis secondary CTAs (e.g., "Gerar Horário").
- **Dark:** Deepest brown (`#3d2b1f`), used on the marketing page for hero and
  pricing CTAs.
- **Outline:** Transparent with brown border and brown text, fills with warm
  beige on hover.
- **Ghost:** Borderless, brown text, reveals a gold underline on hover via
  `::after` pseudo-element. Used for tertiary actions and "Ver mais" links.

All buttons use `!important` on critical properties to override CoreUI's
Bootstrap defaults. Button text is always uppercase with wide letter-spacing.

### Cards

Dashboard cards use 12px border-radius with a 1px `#e0d6cc` border and soft
shadow. Headers have a warm beige (`#f5f0eb`) background. Cards lift slightly
on hover (shadow deepens from 4px/4% to 8px/8%).

The `.zen-state-card` variant is used for schedule status displays — compact
cards with 3px colored left borders and 10% opacity backgrounds.

Marketing cards (`.zen-pricing-card`, `.zen-outcome-card`, `.zen-diff-card`)
use sharp corners and different hover mechanics: border-color shifts to gold
with a lift and shadow increase.

### Tables

Tables use CoreUI's Bootstrap table as a base, overridden with the brand
palette. Headers have a warm beige background, uppercase text at 0.72rem with
wide tracking. Rows are 0.94rem. Row hover uses a subtle `rgba(92,61,46,0.04)`
background. Action triggers (edit/delete icons) fade from 30% to 100% opacity
on row hover.

The `.zen-table` variant removes CoreUI's default styling entirely, using
`border-collapse: separate` with controlled border-spacing for a more
editorial look.

### Sidebar Navigation

The sidebar uses the deepest brown gradient as its background. Navigation items
feature a gold vertical accent bar (3px wide, 60% height) that slides into
view on hover/active states via a height transition. Section headers appear
at 55% opacity, links at 75% opacity. The divider is extremely subtle at 8%
white opacity.

### Input Fields

Form controls inherit the brand border color (`#e0d6cc`) by default. On focus,
the border shifts to `primary` brown with a `0.25rem` focus ring at 45% opacity.
Input groups use the warm surface color (`#f5f0eb`) as their background.

### Toast Notifications

Toasts slide in from the right with the zen reveal easing. They use a glass
background (92% white with 12px blur), 4px left border colored by semantic
state (teal/yellow/red/blue), and 40px soft shadow. Position is fixed top-right.

### Alerts

Both CoreUI alerts (`.alert-success`, `.alert-danger`, etc.) and custom Zen
alerts (`.zen-alert-success`, etc.) use the semantic state color system.
Text uses accessible variants (darker teal/gold/red) to ensure WCAG AA
contrast on the light backgrounds.

### Hero Art (Marketing)

The marketing page hero uses a CSS-only abstract composition: a warm beige
base rectangle, a 12%-opacity gold overlay block, a 6%-opacity brown layer,
vertical/horizontal gold lines, and small brown dots. This creates visual
interest without loading an image. The composition responds to viewport
width, reducing height at smaller breakpoints.

## Responsive Behavior

### Breakpoints

- **>1080px:** Full desktop layout with 3-column outcome grids, 540px hero art
- **780–1080px:** 2-column grids, 380px hero art, nav remains horizontal
- **<780px:** Single-column grids, 280px hero art, nav stacks vertically,
  section padding reduces to 80px
- **<768px:** Mobile-specific overrides for week navigation, availability
  toolbars, sidebar overlay, and login brand panel (converts from vertical
  panel to horizontal banner)

### Mobile Patterns

- Week navigation wraps and centers
- Availability toolbar buttons shrink
- Sidebar gains a dark overlay backdrop
- Full-width buttons on mobile via `.mobile-full-width-btn`
- Login page reorders: brand panel becomes a compact horizontal banner above
  the form

## Accessibility

- **WCAG AA contrast** is maintained for all text/background combinations.
  Accessible text tokens provide darker variants for teal (`#14532d`), gold
  (`#92400e`), and red (`#b91c1c`) text on light backgrounds.
- **Focus visibility:** A `0.25rem` focus ring at 45% brown opacity is applied
  to all interactive elements.
- **Color independence:** Operational states are communicated through both
  color and a 3px left border strip, ensuring distinction for color-blind users.
- **Reduced motion:** All animated transitions are gated behind
  `prefers-reduced-motion: no-preference`.
- **Font smoothing:** `-webkit-font-smoothing: antialiased` is enabled for
  crisp text rendering.

## Governance

1. **No raw hex codes.** All colors must be consumed through semantic tokens.
   If a genuinely new color is needed, it must be added as a token and
   documented.
2. **Tokens describe function, not appearance.** A token named
   `--color-text-secondary` is preferred over `--color-gray-600`.
3. **Single source of truth.** The design token definitions in the YAML
   frontmatter above are authoritative for all visual decisions.
4. **Cross-context consistency.** The marketing site and authenticated
   application share the same token tree. Differences in appearance arise
   only from layout and density choices, never from diverging color values.
5. **The gold is precious.** Gold accents must remain at or below 10% of
   any screen's visual weight. Resist the temptation to "add more gold" —
   restraint is what makes the accent meaningful.
